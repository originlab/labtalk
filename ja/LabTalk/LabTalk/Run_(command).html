構文

run [option] argument
注: runコマンドは行単位で実行されます。 複数行構造体には、構造体イニシエータと同じ行に行継続文字"{"が含まれている必要があります（条件文、関数定義など）。次の例を参照してください。


この文のセットは、runコマンドで正しく動作します。 

if (condition) {
            // True条件文
 } 
else {
            // False条件文
 }

この文のセットは、runコマンドでは正しく動作しません。 

if (condition) 
      {
            // True条件文
      } 
else 
      {
            // False条件文
      }

run.sectionオブジェクトメソッドには行単位の制限がなく、スクリプトファイルの実行の柔軟性が向上します。

オプション：

オプションなし; スクリプトファイルscriptfileNameを実行

構文： run scriptfileName

スクリプトファイルscriptfileNameを実行します。

これはスクリプトを実行する古い方法であり、非推奨です。スクリプトファイルまたはスクリプトファイルの一部を実行するには、runオブジェクトを使用します。

-app UID; 特定のアプリケーションのパラメータを変更するためのダイアログを開く

構文： run -app [UID]

UIDで指定したアプリのパラメーターを変更するダイアログを開きます。

例えば、次のスクリプトを実行して、Graph Makerアプリダイアログを開きます。 

run -auc 1065;

このページに記載されているlist op/opi/opo コマンドを実行すると、UID番号を取得できます。

-au value; プロジェクト全体の再計算モードを変更

構文： run -au value [UID]

必要なOriginのバージョン: 8.5.1以降

UIDを指定しない場合、 valueは次のようになります。

0：再計算モードをなしに設定（再計算を削除する）
1：再計算モードを自動に設定
2：再計算モードを手動に設定

UIDを指定する場合は、UIDで指定した操作のみ再計算モードを変更します。 

run -au 1;  // 再計算モードを自動に設定
run -au 0 779;   //  UID 779を使用した操作をなしに設定(削除)するが、出力は保持

操作のUIDを取得するには、スクリプトウィンドウを開いたままにして、この操作に関連付けられている緑色のロックをクリックし、情報を表示コンテキストメニューを選択します。返されるメッセージには、この操作のUIDが含まれています。

注意： run -au 0; を実行すると、すべての操作オブジェクトが削除されてしまうため、それ以降はrun -au 1; や run -au 2; を使用できなくなります。その意味で、この操作は破壊的です。

-aub value UID; 特定の操作の再計算をブロックまたはブロック解除

構文： run -aub value [UID]

UIDで指定された操作の再計算をブロックまたはブロック解除します。UIDが省略された場合は、全ての操作で動作します。value = 0: ブロック解除、value = 1: ブロック。 

range aa=[book1]sheet1!col(2); //col(2)の再計算がブロックされたと仮定
Uid=aa.getop();
run -aub 0 $(Uid);

操作のUID番号はgetop ()メソッドで取得できます。

-auc UID; 特定の操作のパラメータを変更するためのダイアログを開く

構文： run -auc [UID]

UIDで指定した操作のパラメータを変更するダイアログを開きます。 

run -auc 804; /// 804 は操作UID

このページで紹介したlist op/opi/opoコマンドを実行することでUID番号を取得できます。

アクティブなワークシートが階層型シートの場合、UIDは省略できます。階層シートには単一の操作しか含まれていないためです。次のように実行して、 

run -auc;

直接アクティブなシートでその操作ダイアログを開きます。

-auf; すべての再計算をダーティ化する

構文： run -auf n [m]

必要なOriginのバージョン: Origin 2015 SR1以降

ここでnは 0,1,2の値を取ります。

n 意味
0 現在のワークシートに関連するすべての再計算ロックをダーティ化する
1 現在のワークブックに関連するすべての再計算ロックをダーティ化する
2 現在のプロジェクトに関連するすべての再計算ロックをダーティ化する

ここでmは 0,1の値を取ります。

m 意味
0 すべての再計算ロックをダーティ化する
1 アイドル時の再計算ロックをすべてダーティ化する 
run -auf 1 1;
// "page -uo"と同様
//アクティブなワークブックの全ての操作の再計算をダーティ化する

注意: 一般的に、再計算ロックは、ワークブック/行列ブックの入力データが変更された場合にのみダーティになります。

再計算にプロジェクト変数などの他の変数が含まれる場合は、このコマンドを実行して再計算ロックをダーティにします。

  • 再計算モードが自動の場合、結果は自動的に更新されます。
  • 再計算モードが手動の場合、再計算を再度実行するまで結果は更新されません。
  • run -p auも参照してください。

-aud value; 現在のフォルダの再計算モードを変更（開く）

構文： run -aud value

必要なOriginのバージョン: 2024b以降

現在のフォルダの再計算モードを変更しますが、再帰的ではありません。value次のとおりです。

0：再計算モードをなし(再計算操作を除去）に設定
1：再計算モードを自動に設定
2：再計算モードを手動に設定

現在のフォルダにショートカットウィンドウが含まれている場合、このコマンドにはデフォルトでショートカットウィンドウが含まれます。ショートカットを含めたくない場合は、次を使用します。
構文： run -aud value 0

最後の値0はショートカットウィンドウを除外することを意味します。0以外の値、例えば1は、ショートカットウィンドウを含むことを意味します。

例えば、次のコマンドを実行して、ショートカットウィンドウを除く現在のフォルダ内のすべての操作を削除します。 

run -aud 0 0;
注意： run -aud 0; を実行すると、すべての操作オブジェクトが削除されてしまうため、それ以降はrun -aud 1; や run -aud 2; を使用できなくなります。その意味で、この操作は破壊的です。

-audr value; 現在のフォルダの再計算モードを変更(再帰的)

構文： run -audr value

必要なOriginのバージョン: 2024b以降

現在のフォルダとそのサブフォルダの再計算モードを変更します。valueは次のとおりです。

0：再計算モードをなし(再計算操作を除去）に設定
1：再計算モードを自動に設定
2：再計算モードを手動に設定

現在のフォルダにショートカットウィンドウが含まれている場合、このコマンドにはデフォルトでショートカットウィンドウが含まれます。ショートカットを含めたくない場合は、次を使用します。
構文： run -audr value 0

最後の値0はショートカットウィンドウを除外することを意味します。0以外の値、例えば1は、ショートカットウィンドウを含むことを意味します。

例えば、次のコマンドを実行して、ショートカットウィンドウを除く現在のフォルダ内のすべての操作を削除します。 

run -audr 0 0;
注意： run -audr 0; を実行すると、すべての操作オブジェクトが削除されてしまうため、それ以降はrun -audr 1; や run -audr 2; を使用できなくなります。その意味で、この操作は破壊的です。

-aul value; アクティブレイヤの再計算モードを変更

構文： run -aul value

必要なOriginのバージョン: 2024b以降

アクティブなページ(ワークシート、行列シート、グラフレイヤ)の再計算モードを変更します。valueは次のとおりです。

0：再計算モードをなし(再計算操作を除去）に設定
1：再計算モードを自動に設定
2：再計算モードを手動に設定
注意： run -aul 0; を実行すると、すべての操作オブジェクトが削除されてしまうため、それ以降はrun -aul 1; や run -aul 2; を使用できなくなります。その意味で、この操作は破壊的です。

-aup value; アクティブページの再計算モードを変更

構文： run -aup value

必要なOriginのバージョン: 2024b以降

アクティブなページ(ワークブック、行列ブック、グラフウィンドウ)の再計算モードを変更します。valueは次のとおりです。

0：再計算モードをなし(再計算操作を除去）に設定
1：再計算モードを自動に設定
2：再計算モードを手動に設定

-cr[ filename]; コードビルダワークスペースからファイルを削除

構文： run -cr [<path>\filename]

コードビルダのTemporaryフォルダとUserフォルダから指定されたファイルを削除します。filenameを指定する場合は、フルパスを含める必要があります。filenameが指定されていない場合は、TemporaryフォルダとUserフォルダからすべてのファイルが削除されます。

-cra; コードビルダーワークスペースから一時ファイルとユーザファイルを削除

構文： run -cra

Temporary、User、およびUser [AutoLoad]フォルダを消去し、ユーザーのOrigin.iniファイル内の既存の[OriginCAuto]セクションを削除します(コードビルダーでUser [AutoLoad]にファイルを追加すると、[OriginCAuto]という名前のセクションがOrigin.iniに追加されます。Systemフォルダは変更しません。


-e[p]; Windowsの[ファイル名を指定して実行]ダイアログボックスに入力した場合と同様に、次のtextを実行

構文： run -e text or -ep text

両方とも、Windowsのスタートメニューからファイル名を指定して実行ダイアログボックスに入力したかのように、次のtextを実行します。

プログラムがWindowsシステムパスにある場合、パスは必要ありません。エクスプローラはWindowsのデフォルトシェルであるため、-epは-eと同じです。 

//メモ帳は通常Windowsパスにあるためパスは不要
// Origin's INI ファイルをメモ帳で開くスクリプトはメモ帳の終了を待機
run -ep notepad %YOrigin.ini;
ty -a Notepad closed.;
// ユーザファイルフォルダを開く
run -e explorer %Y; // -ep は -eと同様に動作する
ty -a My UFF is open in Explorer.;
// Word は通常Windowsパスにないため、パスを含める必要がある
string strFile$ = system.path.program$ + "TXTemplate.rtf";
run -ep C:\Program Files (x86)\Microsoft Office\Office12\winword.exe %(strFile$);
ty Done with Word.;
注: run -eとrun -epの違いは、 run -eは外部プログラムを実行してスクリプトの実行を継続するのに対し、run -epは外部プログラムを実行し、外部プログラムが閉じるまでスクリプトを一時停止するという点です。

-lk; 範囲、外部リンク、ヘルプドキュメント、またはメモウィンドウを開くためのリンク

構文： run -lk "range://RangeName" または "http: //URL" または "https: //URL" または "help://HelpPage" または "help://quick/Keyword" または "notes://NotesWindowName"

このコマンドは、内部ウィンドウ、外部リンク、またはヘルプドキュメントページを開くハイパーリンクをサポートしています。
Range://: プロジェクト内の範囲
http://またはhttps://: 外部リンク
Range://: Origin ヘルプドキュメントへのリンク
Range://: 検索するキーワードを指定するオプション付きのクイックヘルプウィンドウを開く(例: run -lk "help://quick/descriptive statistics";)
notes://: ノートウィンドウへのリンク

LabTalkリファレンスセクションのリンク表記を参照してください。

-oc; 名前付きOrigin C関数を実行

構文： run -oc func arg

このコマンドはLabTalkのOrigin C関数を呼び出します。これは、Xファンクション、OGSファイル、LabTalk関数などの間で名前が競合する可能性があるために必要です。また、いくつかのOrigin Cの関数は、LabTalk環境での名前の汚染問題を防ぐために、 run -oc コマンドによって#pragma labtalk(2)を介してのみ呼び出すことができるように書かれています。#pragma labtalk(2)でコンパイルされたOrigin C関数は、LabTalkに直接表示されません。run -oc 経由でのみ使用できます。

-p au; 保留中のすべてのプロジェクト操作を強制的に更新

構文： run -p au;

後続のスクリプトは、Originプロジェクトの保留中の操作がすべて完了するまで待機します。

-p aub; 保留中のすべてのブック操作を強制的に更新

構文： run -p aub;

以降に続くスクリプトは、アクティブブック内のすべての保留中の操作が完了するまで待機します。

-p aubd; 保留中のブック操作とディセンダント操作をすべて更新

構文： run -p aubd;

後続のスクリプトは、アクティブブック内の保留中の操作と、そのディセンダントが完了するまで更新されるのを待ちます。

-p aui UID; 特定の保留中の操作を強制的に完了に更新

必要なOriginのバージョン: Origin 9.1 SR2以降

構文： run -p aui UID

指定されたUIDを持つ操作は、後続のスクリプトを実行する前に強制的に完了に更新されます。

操作のUIDを取得するには、スクリプトウィンドウを開いたままにして、この操作に関連付けられている緑色のロックをクリックし、情報を表示コンテキストメニューを選択します。返されるメッセージには、この操作のUIDが含まれています。

注:保留中の操作は黄色のロックアイコンで示されます。これは、操作のソースデータが変更され、出力が更新されないことを示します。実行中のスクリプトを特定の秒数だけ一時停止するには、sec -pコマンドを使用します。 
// UID 803の操作を強制的に実行して再計算
run -p aui 803;
//保留中の操作を強制的に再計算
run -p au;

-p auid UID; 操作"UID"のディセンダント操作の強制再計算

構文： run -p auid UID;

後続のスクリプトは、操作UIDとそのディセンダントが完了するまで更新されるのを待ちます。

-p auw; 保留中のすべてのシート操作を強制的に更新

構文： run -p auw;

-p auwd; 保留中のシート操作とディセンダント操作を強制的に更新

構文： run -p auwd;

後続のスクリプトは、アクティブシート内の保留中のすべての操作と、そのディセンダントが完了するまで更新されるのを待機します。

-py; Pythonコマンドラインを実行

必要なOriginのバージョン: Origin 2015 SR0以降

構文： run -py Python Statement(s)

Python文を実行します(例：コマンドライン)。Python文は、実行されるPythonコマンドラインを含む文字列変数である必要があります。

Pythonコマンドを直接呼び出すことができます。 

run -py print('Hello Origin');
// ('Hello Origin')と表示するPythonコマンドを実行
// スクリプトウィンドウに "Hello Origin" という文字列を出力

また、PythonコマンドラインをLabTalkの文字列変数に渡すこともできます。 

// PythonコマンドラインをLabTalk文字列変数と定義
// %(CRLF)は、キャリッジリターン（すなわち改行）を示す LabTalk キーワード
str$ = "a = 2 ** 8%(CRLF)print(a)";
// Pythonコマンドラインを実行
run -py %(str$);
// **はPythonにおけるべき乗演算子
//256、すなわち2の8乗を返す

これはオブジェクトメソッド run.python("Python Statements", 0)と同等です。（つまり、optionが0またはデフォルトに設定されている場合）

-pyb; テキストオブジェクトに添付されたPythonコードを呼び出す

必要なOriginのバージョン:2021以降

構文: run -pyb objectName;

テキストオブジェクトのプログラミングタブで入力したPythonコードを実行します。通常、run -pyb コマンドはボタンオブジェクト（ボタンアップでトリガーされるように設定された2番目のテキストオブジェクト）から実行されます。

例えば、テキストオブジェクトを作成し、そのプロパティダイアログを開き、プログラミングタブで名前="abc"を設定して、スクリプトボックスに次のように入力します。 

print ("Hello World!");

2番目のテキストオブジェクト（名前は何でもよいです）を作成し、プロパティ>プログラミングタブを開き、のあとでスクリプトを実行をボタンアップに設定します。 

run -pyb abc;

ボタンをクリックすると、テキストオブジェクトに添付されたコードがトリガーされ、スクリプトウィンドウに"Hello World"が表示されます。

-pye; Python式を評価

必要なOriginのバージョン: Origin 2015 SR0以降

構文： run -pye Python Expression Python式を評価します。Python Expressionは、評価するPython式を含む文字列変数である必要があります。

例えば、 

run -pye 2 ** 5;

// これはPythonの式 2 ** 5, を評価する。Pythonにおいて「**」はべき乗演算子を指す。
// 評価結果として32が出力される。これは2の5乗。

これはオブジェクトメソッドrun.python("Python Expression", 1)と同等です。（つまり、optionが1に設定されている場合）

-pyf; Pythonファイルを実行

必要なOriginのバージョン: Origin 2015 SR0以降

構文： run -pyf Python File Path and Name [arg1 arg2 arg3 arg4 arg5]

Pythonファイルを実行する場合、Python File Path and Nameは、実行する.pyファイルのパスと名前を持つ文字列変数である必要があります。

.pyファイルがユーザファイルフォルダ内にある場合、ファイルパスを指定する必要はなく、指定しない場合は常にフルファイルパスを指定する必要があることに注意してください。

たとえば、Originのユーザファイルフォルダの下にtest.pyファイルがある場合、次のLabTalkスクリプトを実行できます。 

// スクリプトの実行設定がLabTalkになっていることを確認
run -pyf "test.py";
// test.pyファイル内のスクリプトが実行される

.pyファイルのフルファイルパスを指定する必要がある場合もあります。 

// .pyファイルのファイルパスとファイル名を定義
string str$ = system.PATH.PROGRAM$ + "\Samples\Python\ListMember.py";
// Run the .py file

run -pyf %(str$);  
 
// この.pyファイルは PyOriginモジュール内の全ての関数を一覧にする

これはオブジェクトメソッドrun.python("Python Expression", 2)と同等です。（つまり、optionが2に設定されている場合）

引数を呼び出しに追加できます。ユーザファイルフォルダにPythonファイル"test.py"があるとします。 

import sys
if __name__ == '__main__':
    print(len(sys.argv))
    print(sys.argv[1])
    print(sys.argv[2])

変数はLabTalkからPythonファイルに渡すことができます。 

double var1 = 123.456;
string var2$ = 'hello';
run -pyf test.py "$(var1)" "%(var2$)";

-pyp; Originプロジェクトファイルに添付されたPythonファイルを実行

必要なOriginのバージョン: Origin 2015 SR0以降

構文： run -pyp Python File Name

Python File Nameは、Originプロジェクトに添付されているPythonファイル、すなわちコードビルダのプロジェクトフォルダに追加されているPythonファイルを示すべきです。ファイル拡張子（.py）は含めることができますが、必須ではありません。

例として、<Origin EXE Folder>\Samples\Python\パス下のSendDataToWks.opjファイルを開いて次のスクリプトを実行します。 

run -pyp SendDataToWorksheet.py;
// または、次のスクリプトを実行しても同じ結果になります。
// run -pyp SendDataToWorksheet;

注:上記のスクリプトは、ワークシートの「SendDataToWorksheet.pyを実行」ボタンに関連付けられています。

-pyr; OriginのPython環境をリセット

必要なOriginのバージョン: 2021b以降

構文： run -pyr


-w[u] Bookname [colIndex]; 列の数式を実行

構文： run -w or -wu

-w
アンドゥを使用して列の数式を実行する
-wu
アンドゥなしで列の数式を実行することで高速化


// 次のスクリプトは実行の所要時間を表示
// Book1のアクティブなシートのcol(2)の数式
sec;
run -wu Book1 2;
watch;

-w<scope>[L]; アクティブなシート、ブック、フォルダ、プロジェクトの式を実行

(2026)構文： run -w<scope>[L]

有効範囲文字は、 A =アクティブシート、 B =アクティブブック、 F =アクティブフォルダ、 P =プロジェクト

各列の計算の詳細をリストするために文字Lが追加されます。 

run -wbl; 数式による計算を一覧表示するが、自動更新は行われない
run -wb; アクティブなブックに対して数式を実行し、自動更新をトリガーする

-ws; ワークシートスクリプトパネルでスクリプトを実行

構文： run -ws

ワークシートスクリプトパネルでスクリプトを実行します。

-xf; xfnameという名前のXファンクションを実行

構文： run -xf xfname

xfnameという名前のXファンクションを実行します。通常、LabTalk呼び出し可能なXファンクションを直接実行することができますが、現在の作業ディレクトリには同じ名前のOGSファイルがある可能性があるため、 run -xf コマンドを使用するとXファンクションを確実に呼び出すことができます。

-xfm; LabTalkではアクセスできないXファンクション xfnameを起動

構文： run -xfm xfname

LabTalkではアクセスできないXファンクションのダイアログを開きます。
